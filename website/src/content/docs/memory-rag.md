小林以前说「有空爱拿望远镜看星星」，应用当时保存了一条记录。今天他问：「我以前说过周末喜欢做什么？」这段很久以前的对话没有出现在当前消息里。回答需要先去找合适的资料，再让模型组织语言。用同一模型重新猜一遍，不会凭空补齐资料。

**RAG（Retrieval-Augmented Generation，检索增强生成）**有两半：检索负责从资料库找到相关记录，生成负责把找到的资料和当前问题一起交给模型作答。检索不必用向量，也不是一种训练方法。这里的资料是 SQLite 中结构化的用户记忆：每条有主体、正文和状态等字段。聊天原文可以成为短期上下文，日记可以被发布，运行摘要可以帮助接续会话；它们都不进这套用户记忆向量索引。

写入和读取发生在不同时间：先把一条合适的事实存成用户记忆，后台为有效记录建立向量索引；有查询才计算查询向量，比较并返回少量匹配记录。索引可以理解成随原记录保存的一份检索表示，它帮助找记录，最终给模型看的仍是记忆文本等资料。

## 第一步：判断这轮要不要读

| 例子                             | 路径                                                 |
| -------------------------------- | ---------------------------------------------------- |
| 「我以前说过喜欢哪种天文活动？」 | 识别为明确的自我回忆时，第一步强制查询本人的记忆。   |
| 「那就按上次那个安排吧」         | 识别为隐含回忆、当前对话不足且对象明确时，按需查询。 |
| 「晚上好」                       | 普通闲聊不自动预取长期记忆。                         |

```ts title="src/libs/ai.ts（prepareStep 节选）"
if (stepNumber === 0 && recallIntent === "explicit") {
  return { toolChoice: { type: "tool", toolName: "recallMemory" } };
}
```

如果同一步同时查记忆和起草发言，应用会丢弃这一批提前写好的回复，让模型下一步先读结果再答。找不到记忆时应说明，而不是编造。[源码：首步选择](https://github.com/yinyanfr/nyarbot/blob/2433deab6c72ea1ccc44b39c22887badfd638fa1/src/libs/ai.ts#L2036-L2042) · [源码：工具结果与读取预算](https://github.com/yinyanfr/nyarbot/blob/2433deab6c72ea1ccc44b39c22887badfd638fa1/src/libs/ai.ts#L1350-L1416)

## 第二步：只在允许的记录里找

先检查能不能查这个人，再在数据库里限定候选的用户、有效状态、过期时间和可选记录日期。假设小周有一条更贴近查询的观星记忆，它也不能挤进小林的候选。这个顺序很重要：模型看到的应该是权限检查之后的记录，不能把所有候选发给模型再叫它忽略别人的。项目对修改和遗忘另有规则，向量索引不延长记录的有效期。早安场景用 `recent` 按时间取最近三条，也不需要比较关键词和语义。

## 第三步：从字面和语义分别排序

**关键词检索**看实际出现的词。比如找望远镜型号「8×42」，字面匹配很有用。但「天文观测」和「拿望远镜看星星」可能没有足够的共同词。**Embedding（向量表示）**用另一个模型把文本变成一串数。可以把它想象成很多维的坐标：含义相近的输入往往指向相近方向。**余弦相似度**衡量两个向量的方向有多接近；在简化的二维示意里，`[1, 0]` 和 `[2, 0]` 同方向，相似度为 `1`；`[1, 0]` 和 `[0, 1]` 垂直，相似度为 `0`。真实语义模型的坐标没那么容易解释，相似度也只表示相关性线索，不证明事实正确。

nyarbot 通过 Ollama 运行 `bge-m3` 算向量，将记忆向量存在 SQLite。查询文本也用同一模型编码；应用对这一候选范围内的向量进行相似度计算并排序。关键词路径则检查正文与标签。同一个问题得到两张榜单，就需要决定谁在前面。

## 第四步：合并名次，把资料交给模型

**混合检索（Hybrid Search）**同时用两种排名。**RRF（倒数排名融合）**只比较名次：每张榜的第 1 名得 `1/61`，第 2 名得 `1/62`，没上榜就不得分。举一个独立的教学例子：

| 记录 | 字面名次 | 语义名次 | 合并分数      |
| ---- | -------- | -------- | ------------- |
| A    | 第 1     | 没上榜   | `1/61`        |
| B    | 第 2     | 第 2     | `1/62 + 1/62` |
| C    | 没上榜   | 第 1     | `1/61`        |

B 排在最前，因为两条路线都把它视为相关。算法不用硬把关键词计分与余弦值放到同一单位里。

```ts title="src/services/user-memory.ts"
for (const list of [lexical, semanticRows]) {
  list.forEach((row, i) => {
    const score = (fused.get(row.id)?.score ?? 0) + 1 / (60 + i + 1);
    fused.set(row.id, { row, score });
  });
}
```

查询向量的模型请求有 750 毫秒预算；如果等待超时、出错或没有合格向量候选，关键词路径仍可工作。750 毫秒不是整个聊天回合的最长时间。如果两条路线都找不到，工具结果可能是空列表；这只说明目前没找到记录，不证明小林从未说过。回答「我没找到相关记录」比编出一种爱好更符合现有证据。[源码：过滤、预算和排序](https://github.com/yinyanfr/nyarbot/blob/2433deab6c72ea1ccc44b39c22887badfd638fa1/src/services/user-memory.ts#L181-L297) · [源码：索引怎样写入](https://github.com/yinyanfr/nyarbot/blob/2433deab6c72ea1ccc44b39c22887badfd638fa1/src/services/memory-embeddings.ts#L55-L105)
