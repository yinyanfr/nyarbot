小林问：「我以前说过周末喜欢做什么？」如果你只收到这句话，没有见过小林，也没有他的笔记，就无法判断答案。语言模型也遇到同样的问题，只是它能很流畅地说出「你喜欢爬山」。这种看似可信、实际缺乏依据或与事实不符的输出，常被叫作**幻觉（hallucination）**。这门课从一个区别开始：能生成一句话，不等于有足够证据说这句话。

## 模型、服务和应用是三样东西

| 对象              | 它做什么                                                    | 例子                                                |
| ----------------- | ----------------------------------------------------------- | --------------------------------------------------- |
| 大语言模型（LLM） | 根据当前输入，逐步生成文本或结构化输出。                    | nyarbot 用来组织群回复的 DeepSeek 模型。            |
| 模型服务          | 运行模型，提供程序能访问的接口（API），接收请求并返回结果。 | nyarbot 将请求发给模型供应商。                      |
| AI 应用           | 接受人的输入、选择资料、调用模型，并决定如何处理结果。      | nyarbot 负责接收 Telegram 消息、读 SQLite、发回复。 |

**训练**让模型从大量样例中学习语言和其他规律，改变模型内部的参数。**推理（inference）**是使用已经训练好的模型处理一次输入；这里的「推理」指运行模型，不保证它每次都会做出有效的逻辑推导。告诉机器人「我喜欢观星」时，应用可以把这句话存到数据库，后面再取出提供给模型。这个流程没有改动模型参数，也不用重新训练。

## 从输入到输出：一步步想

1. 程序准备输入。比如它把规则写成「只根据给定资料回答，不知道就说明」，把「小林喜欢观星」作为资料，再附上小林的问题。这些交给模型的指令或输入常统称 **Prompt（提示）**。
2. 模型处理输入时，会把文本分成 **token（词元）**。一个 token 可以是字、词的片段或标点；中文字符数、英文单词数都不能直接当成 token 数。具体切分规则由模型相关的分词器决定。
3. 对聊天模型来说，可以把文本生成理解为：根据已经看到的 token，对接下来可能出现的 token 打分，选出一个，再继续。结果可以是自然语言，也可以是应用约定的结构化数据，例如一个工具请求。
4. 程序拿到结果，决定是展示它、执行一个工具，还是停止。模型服务返回结果和用户在 Telegram 看到一条消息，是两个不同的时刻。

模型一次调用能处理的 token 有上限，叫**上下文窗口**。规则、对话历史、工具说明和工具返回的资料都可能占空间，生成也要留预算。把半年群聊都塞进去会增加成本和等待时间，还可能挤掉真正相关的资料。后面会看到，应用只放近期聊天和摘要，需要时再查长期记忆。

## 在代码里找那条分界线

下图是教学示意。左边是程序可以控制的输入；中间是模型服务；右边仍需要程序来解释和处理。

```text
规则 + 可见对话 + 问题 + 可用工具
             ↓
          模型调用
             ↓
       文本或工具请求
             ↓
     应用决定是否查资料、发送或停止
```

打开[固定版本中的主轮次请求](https://github.com/yinyanfr/nyarbot/blob/2433deab6c72ea1ccc44b39c22887badfd638fa1/src/libs/ai.ts#L2016-L2061)，先只找 `model`、`system`、`messages`、`tools` 四项：分别对应哪个模型、系统规则、消息内容和可用动作。`generateText` 来自 **AI SDK**，这是程序用来调用模型与处理返回值的 TypeScript 工具包，它本身不是模型。即使暂时看不懂某项内部的代码，也可以继续读。

## 小练习：哪些问题缺资料？

假设应用只传了用户的当前问题和一条「不要猜」的规则。分别判断模型有没有足够的依据回答：「望远镜一般用来做什么？」「我上次说我用的是哪台望远镜？」「今天活动改到几点了？」

<details>
<summary>参考答案</summary>

第一问是常识，模型可能根据训练学到的知识回答。第二问需要过去的群聊或已保存的个人记忆。第三问需要当前通知等新证据。模型可能把三问都答得流畅，但流畅无法区分这三种证据条件。应用需要为后两问提供资料，或者明确承认资料不足。

</details>
