小林 @ 机器人问：「我以前说过周末喜欢做什么？」假设数据库记录如下，最近聊天没有答案。请先在纸上做一遍，代码用来验证你的推演。

| 主体 | 记录                 | 状态   | 用「周末爱好」查找时会怎样   |
| ---- | -------------------- | ------ | ---------------------------- |
| 小林 | 有空爱拿望远镜看星星 | 有效   | 假设只有语义检索能找到。     |
| 小林 | 周末爱好是钓鱼       | 已失效 | 字面命中，但不该被使用。     |
| 小周 | 周末爱好是做面包     | 有效   | 字面命中，但问的是小林自己。 |

## 任务一：画出正常路径

在纸上写出 **Telegram → handler → runtime → 模型 → 记忆工具 → 模型 → Telegram**。在每个箭头旁写出传递的东西：事件、待执行函数、带规则的输入、查询请求、检索证据，还是待发回复？标出这三道关卡分别在哪里：

1. 谁限制这一轮首先得查记忆？
2. 谁阻止小周的记录和失效记录进入排名？
3. 谁真的把回复交给 Telegram？

<details>
<summary>参考答案</summary>

Telegram 把更新交给 handler，handler 登记事件、将待执行函数交给 runtime；轮到任务时，`generateAiTurn` 组织模型输入，并在首步指定 `recallMemory`。工具根据请求和当前用户查 SQLite，检索服务按主体、有效状态等过滤，再用混合排名选出「望远镜看星星」。工具结果回到模型，模型才组织回复并请求 `send_message`。这个请求先产生待发文本，handler 的 `sendAiMessages` 随后做真正的投递。

对照[一条消息的链路](../message-to-reply/)、[工具的两段执行](../tool-calling/)和[候选范围与排序](../memory-rag/)。

</details>

## 任务二：同一句「机器人没答对」，可能发生了什么？

分别分析三种独立情况。答题格式：出问题的阶段、程序现在还知道什么、该继续做什么。

| 故障                          | 给定线索                                                        |
| ----------------------------- | --------------------------------------------------------------- |
| A：向量服务超时               | 关键词查询成功完成，但候选为空。                                |
| B：同一步先查又抢答           | 模型同时发出 `recallMemory` 和「你喜欢钓鱼」的 `send_message`。 |
| C：模型有可用回复，群里却没有 | 应用收到了待发文本，但 Telegram 发送请求报错。                  |

<details>
<summary>参考答案</summary>

- **A：检索阶段。** 可降级到关键词；本例没有合格记录，所以用「这次没找到」说明限制。不能拿失效记录或别人的命中补答案，也不能断言小林从未说过。
- **B：工具循环阶段。** 这条抢答没有读过工具结果。应用丢掉本步的待发文本，再让后续步骤基于实际检索结果作答。
- **C：投递阶段。** 先看 Telegram 调用和这轮发送结果。模型推理和检索可能都做对了，重新询问模型并不能解释投递错误。

</details>

## 任务三：学会读一个测试

在[源码地图](../source-map/#按问题选择测试)运行「先查再答」和「语义与字面召回」两个测试。阅读测试时找三样东西：

1. **安排输入**：给了什么假模型、假向量或假数据？
2. **执行**：代码里哪一行调用了被测流程？
3. **断言**：程序检查了哪些结果？哪些真实服务行为没有被覆盖？

<details>
<summary>参考答案</summary>

「先查再答」跑的是真实 SDK 循环，用假模型和假记忆查询返回「喜欢红茶」；断言后一步读到了工具结果并生成预期回复。「语义与字面召回」用 SQLite 和注入的假向量来验证候选、排序和范围，不证明某个线上嵌入模型一定找得到某句改写。两条都通过，也不能代替 Telegram 实际投递的验收。

</details>

到这里，你已经能把一条「AI 没答对」拆解成可单独验证的问题：输入有没有足够的资料，权限和排序是否给出了合适的证据，模型有没有先读再答，最后应用有没有完成投递。把这套定位方式用到其他 AI 应用，比记住一长串缩写更有用。
